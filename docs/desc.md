## 0. 三分钟速览

### 0.1 一句话

**把一段信息（文本或黑白小图）变成一串 0/1，再用"改变图像中某些频率条纹的强弱关系"的方式写进图片；肉眼几乎看不出，但知道规则的程序能把 0/1 读回来。**

### 0.2 三个按钮

| 按钮 | 做什么 | 关键点 |
|---|---|---|
| **加水印** | 把载荷写进图片 | 只改亮度通道的 8×8 块 DFT 中频系数；只写 25% 的块；PSNR 约 44–50 dB |
| **提取信息** | 从图片读回载荷 | 同样的分块和选块规则；输出每个比特的"软信息"，再判决 0/1 |
| **去水印** | 把水印信号抹掉 | 把每对系数的幅值拉平到平均值；水印读不出来，图像反而更接近原图 |

注意：**提取信息 ≠ 去水印**。前者是"读"，后者是"抹"。老师要看的正是这两个动作分开。

### 0.3 一张图看清数据流

```
加水印：
  载荷(文本/二值图)
        │ UTF-8 / 二值化
        ▼
      比特 0/1 ──►（可选）Polar 编码 ──► 选块、重复、交织
                                              │
  原图 ──► 转 YCrCb ──► 取 Y ──► 8×8 分块 ──► 2D-DFT ──► 改中频系数对幅值
                                              │
                                              ▼
                                         2D-IDFT ──► 回填 Y ──► 转回 BGR ──► 取整 ──► 含水印图

提取信息：
  含水印图 ──► 取 Y ──► 8×8 分块 ──► 2D-DFT ──► 算每对幅值差 ──► 除以局部能量
        ──► 每个比特的多个副本取平均 ──►（可选）Polar 译码 ──► 0/1 ──► 文本/图

去水印：
  含水印图 ──► 取 Y ──► 分块 DFT ──► 只处理"嵌入时用过的块"
        ──► 把每对幅值拉平到两者平均 ──► IDFT ──► 回填 ──► 去水印图
```

### 0.4 必须记住的数字（lena，128 bit 文本）

| 项目 | 数值 | 含义 |
|---|---|---|
| 载荷 | `DEMO 水印 2027` = 16 字节 = 128 bit | 其中 1 的个数是 53 个（41.4%） |
| 全图平均中频幅值 B̄ | 41.52 | 决定"改多重"的尺子 |
| 目标幅值差 D | 1.2 × 41.52 = 49.82 | 每个系数对要拉开的差距 |
| 使用块数 | 128 × 8 = 1024 / 4096 | 只改 25% 的块 |
| 加水印后 PSNR / SSIM | **49.93 dB / 0.9972** | 肉眼基本看不出 |
| 提取 BER / NC | **0 / 1.0** | 128 bit 全对 |
| 去水印后 PSNR | **51.68 dB** | 比含水印时还接近原图 |
| 去水印后再提取 BER | **0.2891**（37/128 错） | 文本已经乱码，水印不可读 |

### 0.5 三个绕不开的权衡

```
        容量（能藏多少）
              /\
             /  \
            /    \
           /      \
  不可见性 ──────── 鲁棒性
   （看不出）      （扛折腾）
```

- 想藏得多 → 用的块多、重复少 → 画质差、容易错。
- 想看不出 → 改得轻 → 一压缩就丢。
- 想扛折腾 → 改得重、重复多 → 画质差、容量小。

**整篇论文和所有参数，都是在这个三角形里找平衡。** 答辩时只要能把这句话讲清楚，很多问题都能接住。

## 1. 系统全景

### 1.1 三个动作的输入输出

| 动作 | 输入 | 输出 | 失败会怎样 |
|---|---|---|---|
| 加水印 | 原图 + 载荷 + 参数 | 含水印图 + 嵌入信息 | 图太大/载荷太长 → 容量不足报错 |
| 提取信息 | 待检图 + 载荷长度 + 同样的参数 | 0/1 + 软信息 + BER/NC | 种子不对 → 读出来是乱码（BER≈0.5） |
| 去水印 | 含水印图 + 同样的参数 | 去除图 + 去除后再提取的 BER | 参数不对 → 抹错位置，水印还在 |

### 1.2 模块分层

```

│ gui.py（PyQt5）                                │
│ 只负责：收集参数、调用 API、显示图像和数字        │
└───────────────┬───────────────────────────────┘
                │ 不碰算法细节
┌───────────────▼───────────────────────────────┐
│ pipeline.py                                   │
│ embed / extract / remove / capacity_bits      │
│ 负责：颜色空间、分块、选块、纠错码接入、回填      │
└───────────────┬───────────────────────────────┘
┌───────────────▼───────────────────────────────┐
│ dft_watermark.py                              │
│ 分块 DFT、系数对调制、软信息、拉平、布局          │
├───────────────────────────────────────────────┤
│ codes.py  metrics.py  attacks.py  payload.py  │
│ 纠错码接口 指标       攻击模拟    载荷编解码     │
└───────────────────────────────────────────────┘
```

这样分层的好处：**同一套核心库，既能被界面调用，也能被脚本批量跑实验**。论文里可以说"算法与界面解耦"。

### 1.3 "密钥"到底是什么

本系统没有密码学意义上的密钥，所谓"钥匙"是下面这组**协议参数**：

| 参数 | 默认值 | 作用 |
|---|---|---|
| 载荷比特数 `n_bits` | 128（文本 16 字节） | 决定选多少块 |
| 重复次数 `max_repeat` | 8 | 决定每个比特写几份 |
| 选块种子 `seed` | 2027 | 决定用哪 1024 个块 |
| 系数对 `pairs` | 三组中频对 | 决定改哪些频率 |
| 块大小 `block_size` | 8 | 决定分块网格 |

提取端必须和嵌入端**完全一致**，否则块都对不上。种子不对的实测：BER 0.42–0.52，软信息平均幅度从 1.21 掉到 0.20 左右——基本等于瞎猜。

> 答辩注意：种子是"排列密钥/访问控制"，不是加密。它防的是"不知道规则的人"，不防"拿到代码的人"。真正的商业系统还需要密钥派生、认证、抗逆向等，别把它说成密码学安全。

## 2. 图像基础

### 2.1 像素、通道、uint8

一张彩色图在内存里是一个三维数组：

```
高 H × 宽 W × 通道 3
每个元素 0–255 的整数（uint8）
```

- 0 = 最暗，255 = 最亮。
- 三个通道分别代表蓝、绿、红（OpenCV 的顺序是 **BGR**，不是 RGB）。
- 灰度图只有二维 `H × W`，没有通道维。

**为什么用 uint8**：显示器、JPEG、PNG 都是 8 位；文件小、处理快。代价是**只能存整数**，所有浮点计算结果最后都要四舍五入回去，这就是后面"量化误差"的来源。

### 2.2 为什么代码里是 BGR

OpenCV 的 `imread` 默认按 BGR 读，`cvtColor` 的常量也叫 `COLOR_BGR2YCrCb`。这是历史习惯，不影响算法，但写代码时别把 R 和 B 弄反。界面显示时用 `QImage.Format_BGR888`，也是同一套顺序。

### 2.3 YCrCb：为什么只改亮度

彩色图可以拆成"亮度 + 两个色度"：

```
Y  = 0.299 R + 0.587 G + 0.114 B          （亮度）
Cr = (R - Y) × 0.713 + 128                 （红色差）
Cb = (B - Y) × 0.564 + 128                 （蓝色差）
```

OpenCV 的 `COLOR_BGR2YCrCb` 输出顺序是 `Y, Cr, Cb`。代码里只取 `ycc[:, :, 0]`，也就是 Y。上面的公式是 8 位表示（中心 128）；代码先把 BGR 归一化到 0–1，再转 YCrCb，所以浮点版本的 Y 在 0–1、Cr/Cb 中心在 0.5，取 Y 时再乘回 255。

**为什么只改 Y：**

1. **人眼对亮度细节和色度细节的敏感度不同**。同等强度下，改色度更容易出现彩色斑点，改亮度更自然。
2. **JPEG 通常对色度做 4:2:0 下采样**：色度分辨率只有亮度的一半。水印写在色度里，第一次存 JPEG 就可能被砍掉。
3. **灰度图天然只有 Y**，彩色图和灰度图可以共用一套流程，不用写两个版本。

**代价**：彩色图在 BGR → YCrCb → 改 Y → YCrCb → BGR 的往返中，会有一次颜色换算和取整误差。实测对 PSNR 的影响小于 0.1 dB，可以接受。

### 2.4 灰度图分支

`pipeline._to_plane()` 里：

- 如果 `img.ndim == 2`，直接返回 `img.astype(float64)`，`carrier=None`。
- 如果是 4 通道（带 alpha），先丢掉 alpha，只留 BGR。
- 否则转 YCrCb，返回 Y 平面和整个 YCrCb 图（后面回填用）。

回填时 `_from_plane()` 把修改后的 Y 放回 `carrier[:, :, 0]`，再转回 BGR；如果是灰度图，直接 `rint` 回 uint8。

### 2.5 为什么要补边到 8 的倍数

8×8 分块要求高、宽都能被 8 整除。比如 500×500 的图，补到 504×504：

```
ph = (-H) % 8
pw = (-W) % 8
np.pad(..., mode="edge")   # 用最边上的一行/一列复制填充
```

**为什么用 edge 复制而不是补 0**：补 0 会在边缘制造一条黑边，DFT 后产生强烈的高频，既影响画质，也让边缘块的统计特性和别的块不一样。复制边缘像素最接近"图像本来就这样"。

**注意**：嵌入后输出的图尺寸会变成补边后的尺寸（最多大 7 像素）。提取端也必须做同样的补边，否则块网格错位，水印全废。`prepare_reference()` 就是给 PSNR 比较用的"同样补过边的原图"。

### 2.6 浮点与取整：误差从哪来

整个算法内部用 `float64`：

```
uint8 图 → float64 → 分块 → FFT → 改系数 → IFFT → clip(0,255) → rint → uint8
```

最后一步 `np.rint` 是**四舍五入到整数**。一个像素的浮点值如果是 127.4，存成 127；如果是 127.6，存成 128。这个误差最多 0.5 个灰度级，但它是**不可逆**的：存成 uint8 之后，你无法知道原来小数部分是多少。

这个小小的取整误差，后面会解释两件事：

- 为什么去水印后 BER 不是精确的 0.5；
- 为什么"去水印"不能把图恢复到 100% 原图。

## 3. DFT：换一个角度看图

### 3.1 一维 DFT 的直觉

一段长度为 N 的信号，可以拆成 N 个不同频率的正弦/余弦波：

```
X[k] = Σ(n=0..N-1) x[n] · e^(-j2πkn/N)
```

- `k` 是频率编号：k=0 是直流（平均值），k 越大变化越快。
- `X[k]` 是复数：**模长**表示这个频率有多强，**角度**表示这个波的相位（位置偏移）。
- 逆变换把 N 个波重新叠加回原信号。

音乐类比：一段音乐可以拆成"低音多强、中音多强、高音多强"；DFT 就是把信号拆成"每种频率多强"。

### 3.2 二维 DFT

图像是二维的，所以对 8×8 块做二维 DFT：

```
C(u,v) = Σ(m=0..7) Σ(n=0..7) f(m,n) · e^(-j2π(um + vn)/8)
```

- `f(m,n)` 是块里第 m 行、第 n 列的像素值。
- `C(u,v)` 是第 (u,v) 个频率系数，复数。
- `u` 对应行方向（竖直），`v` 对应列方向（水平）。
- 逆变换：

```
f(m,n) = (1/64) Σ(u) Σ(v) C(u,v) · e^(+j2π(um + vn)/8)
```

NumPy 的 `np.fft.fft2` 默认就是上面的符号约定，`np.fft.ifft2` 自带 `1/64`。

### 3.3 (u,v) 到底是什么

把每个 (u,v) 想成一张 8×8 的"明暗条纹模板"：

- `(0,0)`：全图同一个值 → 直流，等于块的平均亮度。
- `(1,0)`：竖直方向一个周期 → 一道横向的明暗渐变。
- `(0,1)`：水平方向一个周期 → 一道竖向的明暗渐变。
- `(1,2)`：竖直 1 个周期、水平 2 个周期 → 斜向的条纹。
- `(4,4)`：棋盘格 → 二维 Nyquist，变化最快。

**频率越高 = 条纹越密 = 图像里越细的细节。**

### 3.4 幅度与相位

一个复数可以写成：

```
C = |C| · e^(jθ)
```

- `|C|`：幅度，这条条纹有多强。
- `θ`：相位，这条条纹的位置往哪偏。

本系统**只改幅度，不改相位**：

```
C' = |C'| · e^(jθ)
```

**为什么不动相位**：相位承载了图像的结构和边缘位置。把相位改乱，画面会出现重影、错位、振铃，非常难看。只改幅度，相当于"把某条条纹调亮/调暗一点"，视觉上更温和。

### 3.5 共轭对称：为什么必须改镜像位置

真实图像的像素都是实数。实数的二维 DFT 有一个性质：

```
C(u,v) = conj( C((8-u) mod 8, (8-v) mod 8) )
```

也就是说，`(u,v)` 和它的"镜像" `(8-u, 8-v)` 是共轭的。比如：

```
C(1,2) = conj(C(7,6))
C(2,1) = conj(C(6,7))
C(4,4) = conj(C(4,4))   → 自己共轭，所以是实数
```

如果你只改 `C(1,2)` 而不改 `C(7,6)`，逆变换出来的像素会是复数（有虚部），不再是真实图像。代码里每次修改都同步：

```python
cu, cv = (8 - u) % 8, (8 - v) % 8
spec[..., cu, cv] = np.conj(new_value)
```

最后 `np.real(ifft2(...))` 取实部，理论上虚部已经是 0，取实部只是保险。

### 3.6 为什么分块，而不是整张图做 DFT

| 做法 | 优点 | 缺点 |
|---|---|---|
| **整张图 DFT** | 频率分辨率高，全局统计稳 | 一处被裁剪/改动会影响所有频率；需要全局同步；计算量大 |
| **8×8 分块 DFT** | 局部损坏只影响少数块；和 JPEG 的 8×8 网格对齐；实现简单 | 频率分辨率只有 8 个点，比较粗 |

我们选分块，核心原因是**和 JPEG 对齐**：JPEG 也是 8×8 分块做 DCT。水印块和 JPEG 块落在同一个网格上，压缩时的量化误差不会因为"网格错位"而被放大。另外，裁剪掉一块，只会破坏那块区域里的水印副本，不会把整张图的水印一起毁掉。

### 3.7 频率半径与自然图像频谱

频率半径：

```
r(u,v) = sqrt(u² + v²)
```

我们用的三对系数：

| 系数对 | 半径 | 说明 |
|---|---|---|
| (1,2) / (2,1) | √5 ≈ 2.24 | 中低频，方向互换 |
| (2,3) / (3,2) | √13 ≈ 3.61 | 中频，方向互换 |
| (1,3) / (3,1) | √10 ≈ 3.16 | 中频，方向互换 |

8×8 块的最大半径是 `(4,4)` 的 √32 ≈ 5.66。所以这三对都在**中低频到中频**，不是最高频。

自然图像的功率谱大致随半径增大而衰减（低频能量大，高频能量小）。**同一半径上的两个系数，天然幅值比较接近**——这正是我们能用一个不大的差值去"压过"自然差值的前提。

### 3.8 为什么必须是"等半径"对

这是整个算法最关键的实验结论之一。

如果选 `(1,1)` 和 `(2,2)` 这种**半径不同**的对：

- `(1,1)` 半径 1.41，低频，自然幅值通常很大；
- `(2,2)` 半径 2.83，中频，自然幅值通常小很多；
- 两者天生的差，可能远远大于我们想嵌入的差值 D。

结果：符号由图像内容决定，不由水印决定。实验中把系数对换成 `(1,1)/(2,2)` 后，**无论强度取 0.2 还是 0.5、无论攻击轻重，BER 恒为 0.617**——这叫"系统性失效"，重复多少次都没用。

**答辩金句**：等半径不是审美选择，是数学前提。半径不同，两个系数的先验能量不同，差值符号就被图像内容绑架了。

### 3.9 为什么不动 DC 和 Nyquist

- `(0,0)` 是直流，等于块的平均亮度。改它会让整块变亮/变暗，非常明显；JPEG 也会重点保护 DC。
- `(4,4)` 是二维 Nyquist，棋盘格，改它容易产生高频噪点。
- 代码里的 `validate_pairs()` 会直接拒绝这两个位置，也会拒绝"两个系数对共用同一个镜像位置"的情况，避免互相覆盖。

## 4. 载荷 → 比特

### 4.1 文本：UTF-8 + 定长补零

`payload.text_to_bits(text, n_bytes)`：

```
text.encode("utf-8") → 字节串
不足 n_bytes 就补 0x00
超过 n_bytes 就报错
每个字节 → 8 个比特（高位在前）
```

例子：`DEMO 水印 2027`

```
D    E    M    O    空格  水        印        空格  2    0    2    7
44   45   4D   4F   20   E6 B0 B4  E5 8D B0  20   32   30   32   37
```

共 16 字节 = 128 bit。十六进制：

```
44454d4f20e6b0b4e58db02032303237
```

- ASCII 字符（D、E、M、O、空格、数字）各 1 字节。
- 中文"水""印"各 3 字节（UTF-8）。
- 所以**16 字节不等于 16 个汉字**，中文最多 5 个汉字（15 字节）+ 1 个 ASCII。

**为什么定长**：提取端必须知道要读多少 bit。如果长度可变，就得先传长度，反而更复杂。定长 + 补零最简单。

**补零的副作用**：文本里不能出现 `\x00`，否则 `bits_to_text()` 会在第一个 0 处截断。对短文本水印来说没问题。

### 4.2 二值图：32×32 = 1024 bit

`payload.image_to_bits(img, (32, 32))`：

```
彩色 → 灰度
缩放到 32×32（INTER_AREA）
像素 > 128 → 1，否则 0
按行优先展开成 1024 个 bit
```

提取时 `bits_to_image()` 反过来 `reshape(32,32) * 255`，得到黑白图。

**为什么是 32×32**：512×512 的图有 4096 个块，1024 bit 用 R=4 正好写满；再大就放不下（除非换更大的图）。32×32 的 logo 在界面上也看得清。

### 4.3 容量怎么算

```
块数 = ceil(H/8) × ceil(W/8)
裸容量 = 块数 × 1 bit
```

| 图像 | 块数 | 裸容量 | R=8 时可承载的信息 bit | 约合文本 |
|---|---|---|---|---|
| 512×512 | 4096 | 4096 bit = 512 字节 | 512 bit = 64 字节 | 64 个 ASCII / 21 个汉字 |
| 480×512 | 3840 | 3840 bit = 480 字节 | 480 bit = 60 字节 | 60 个 ASCII / 20 个汉字 |
| 1024×1024 | 16384 | 16384 bit = 2048 字节 | 2048 bit = 256 字节 | 256 个 ASCII / 85 个汉字 |

当前默认载荷 128 bit，R=8，只用 1024 个块（512×512 图的 25%）。

**二值 32×32（1024 bit）**：`full_repeat = 4096 // 1024 = 4`，`max_repeat=8` 会被自动压到 4，正好用满 4096 个块。所以二值模式不是"放不下"，而是"重复次数降到 4，鲁棒性会差一些，PSNR 也会低一些"。

### 4.4 文本容量的坑

- 容量按**字节**算，不按字符算。一个汉字 3 字节，一个 emoji 4 字节。
- 定长补零意味着：写 5 个字节的文本，也会占满 16 字节的容量。
- 文本太长会直接报错，不会自动截断——这是故意的，避免"以为写进去了，其实被截了"。

## 5. 比特 → 块：布局、重复、交织、密钥

### 5.1 块怎么编号

`to_blocks()` 把图像 reshape 成 `(H/8, W/8, 8, 8)`，块按**行优先**编号：

```
块 0   块 1   块 2   ...
块 64  块 65  块 66  ...   （512×512 时每行 64 块）
...
```

`from_blocks()` 是它的逆操作，把块拼回图像。

### 5.2 `plan_layout()` 的逻辑

```python
full_repeat = n_blocks // n_bits
repeat = full_repeat if max_repeat is None else min(full_repeat, max_repeat)
used = repeat * n_bits

if max_repeat is None:
    positions = 0..used-1          # 用最前面的块，不随机
else:
    positions = sort(random_permutation(n_blocks)[:used])
```

对 512×512、128 bit、R=8：

```
full_repeat = 4096 // 128 = 32
repeat = min(32, 8) = 8
used = 8 × 128 = 1024
positions = 从 4096 个块里随机挑 1024 个，升序排列
```

**为什么随机挑**：如果总是用最前面的 1024 个块，水印会集中在图像左上角，一眼就能看出差异图上的方块，而且裁剪左上角就全毁了。随机挑让水印均匀分散在全图。

**为什么升序排列**：见 5.4，这是提取端能正确合并的前提。

### 5.3 为什么是 `k % n_bits`

代码：

```python
block_bits[positions] = coded[np.arange(positions.size) % coded.size]
```

`positions` 是升序的块号。第 i 个被选中的块，承载第 `i % n_bits` 个比特。

对 128 bit、R=8：

```
positions[0]   → bit 0
positions[1]   → bit 1
...
positions[127] → bit 127
positions[128] → bit 0     ← 第二份
positions[129] → bit 1
...
positions[1023] → bit 127  ← 第八份
```

所以每个比特正好有 8 个副本。

### 5.4 为什么必须排序：`gather_soft` 的正确性

提取端：

```python
soft_blocks = extract_block_soft(plane)      # 每个块的软值
soft = gather_soft(soft_blocks[positions], n_bits, repeat)
```

`gather_soft` 做的是：

```python
values = soft_at_positions[:repeat*n_bits].reshape(repeat, n_bits)
return values.mean(axis=0)
```

为什么这样重排，第 j 列正好是第 j 个比特的所有副本？

因为 `positions` 升序，第 i 个位置的块承载 `i % n_bits`。把前 `R×n` 个位置按 `(R, n)` 排成矩阵：

```
第 0 行：bit 0, 1, 2, ..., n-1
第 1 行：bit 0, 1, 2, ..., n-1
...
第 R-1 行：bit 0, 1, 2, ..., n-1
```

每一列就是同一个比特的 R 个副本。`mean(axis=0)` 就是按列平均。

**如果 positions 不排序**，第 i 个位置和 `i % n` 的对应关系就乱了，reshape 出来的列不再是同一个比特，提取必错。所以排序不是可选项，是正确性的一部分。

### 5.5 重复的作用：把噪声压下去

假设每个副本的观测是：

```
y_i = s + n_i
```

`s` 是水印信号（+D 或 -D），`n_i` 是噪声。R 个副本取平均：

```
ȳ = s + (1/R) Σ n_i
```

如果噪声独立、方差 σ²，平均后的噪声方差是 σ²/R，标准差是 σ/√R。

R=8 时，噪声标准差降到原来的 1/√8 ≈ 0.354，也就是**信噪比提高约 9 dB**。这就是"多抄几份"的威力。

直观理解：一个副本被破坏，最多把平均值拉偏 `2s/R`；R=8 时只偏 25%，其他 7 份还是对的，符号不变。要破坏一个比特，至少得同时破坏一半以上的副本。

### 5.6 稀疏嵌入：只改 25% 的块

`max_repeat=8` 时，128 bit 只用 1024 个块，剩下 3072 个块**一个像素都不改**。

| 方案 | 使用块数 | PSNR（5 图均值） | JPEG Q80 |
|---|---|---|---|
| 写满全图（R=32） | 4096 | 约 39 dB | BER 0 |
| 稀疏 R=8 | 1024 | **约 44 dB** | BER 0 |

**为什么 PSNR 能高约 5 dB**：PSNR 是按全图均方误差算的。只改 1/4 的块，MSE 大约降到 1/4，`10 log10(4) ≈ 6 dB`；实测约 5 dB，因为块的纹理不同，不是严格线性。

**代价**：每个比特只有 8 份，而写满全图有 32 份，抗攻击能力下降。这是"画质 vs 鲁棒性"的直接交换。

### 5.7 交织：为什么裁剪 20% 还能 BER=0

假设没有 `k % n` 的交织，而是"前 8 个块写 bit 0，接着 8 个块写 bit 1……"。那么裁剪掉左上角 20%，可能把某几个比特的 8 份全毁，这几个比特必错。

有了 `k % n`：

- 被裁剪区域里的块，在升序 positions 里是连续的一段；
- 它们的比特编号是连续的 `k, k+1, k+2, ...`，对 128 取模后，**分散到 128 个不同的比特**；
- 每个比特最多损失 1–2 份，剩下 6–7 份还在，平均后符号不变。

所以裁剪 5%/10%/20% 的实测 BER 都是 0，尽管 20% 裁剪的攻击 PSNR 已经掉到 21.27 dB（图已经很难看）。**图像被破坏 ≠ 水印被破坏**，这是两件事。

### 5.8 种子错了会怎样

实测（lena，正确种子 2027）：

| 提取种子 | BER | 软信息平均幅度 |
|---|---|---|
| 2027（正确） | 0.0000 | 1.2111 |
| 2028 | 0.5156 | 0.2383 |
| 1 | 0.4219 | 0.2049 |
| 999 | 0.4453 | 0.2224 |

种子错了，选块位置全错，读到的是自然图像的随机幅值差，软信息幅度从 1.21 掉到 0.2 左右，BER 接近 0.5。

**注意**：0.42–0.52 不是精确 0.5，原因和去水印后一样：自然图像的幅值差不是零均值，128 bit 样本也小。见第 10.6 节。

## 6. 嵌入数学（核心）

### 6.1 符号表

| 符号 | 含义 |
|---|---|
| `C(u,v)` | 块在频率 (u,v) 的复数系数 |
| `m1, m2` | 一对系数的幅度 `m1 = abs(C1), m2 = abs(C2)` |
| `m̄` | 两个幅度的平均 `(m1+m2)/2` |
| `B̄` | **全图**所有选中系数幅值的平均（全局尺度基准） |
| `α` | 嵌入强度，默认 1.2 |
| `D` | 目标幅值差（带符号） |
| `s` | 比特对应的符号：bit=1 → +1，bit=0 → −1 |
| `shift` | 每个系数幅度要移动的量 |

### 6.2 每个块做什么

对每个**被选中的块**：

1. 做 8×8 二维 DFT，得到 64 个复数系数。
2. 取三组等半径中频对：
   - `(1,2)` 和 `(2,1)`
   - `(2,3)` 和 `(3,2)`
   - `(1,3)` 和 `(3,1)`
3. 对每一对，计算当前幅度 `m1, m2`。
4. 把幅度差调整到目标值 `D`，符号由比特决定。
5. 保持相位不变，写回系数。
6. 同步修改共轭镜像位置。
7. 三对都做完后，逆变换回像素。

**同一个块的三对系数承载同一个比特**。所以一个块内其实有 3 次重复；提取时先把三对的差值平均，再跨块平均。

### 6.3 目标差值 D

代码（`embed_block_bits`）：

```python
m = 0.5 * (m1 + m2)
delta = min(0.5 * strength * base, 0.9 * m)
want = sign * 2 * delta
```

把它写成公式：

```
D = s · min( α · B̄ , 1.8 · m̄ )
```

其中 `s = +1`（bit 1）或 `-1`（bit 0）。

**两项分别是什么意思：**

- `α · B̄`：由嵌入强度和全图平均能量决定的"标准力度"。默认 `1.2 × 41.52 = 49.82`。
- `1.8 · m̄`：**安全上限**。如果目标差值比这对系数本身的平均幅度还大很多，调整后其中一个幅度会变成负数（幅度不能为负），所以必须压住。

**为什么上限是 1.8 m̄**：

调整后两个幅度是：

```
n1 = m̄ + D/2
n2 = m̄ - D/2
```

要让 `n2 ≥ 0`，需要 `D/2 ≤ m̄`，即 `D ≤ 2m̄`。取 1.8 m̄ 留 10% 余量，保证 `n2 ≥ 0.1 m̄ > 0`。

### 6.4 中点保持：`shift` 怎么来的

我们希望：

```
n1 - n2 = D
(n1 + n2)/2 = m̄     （中点不变）
```

解这两个方程：

```
n1 = m̄ + D/2
n2 = m̄ - D/2
```

而当前幅度是 `m1, m2`，所以每个系数要移动：

```
shift = (D - (m1 - m2)) / 2
n1 = m1 + shift
n2 = m2 - shift
```

验证：

```
n1 - n2 = (m1 - m2) + 2·shift
        = (m1 - m2) + D - (m1 - m2)
        = D
n1 + n2 = m1 + m2 = 2m̄
```

**为什么要保持中点**：中点代表这对系数的"总能量"。只改差值、不改中点，相当于"把能量从一条条纹挪到另一条条纹"，整体亮度/能量不变，画质更自然。去水印时把差值拉回 0，也就是回到这个中点，所以能顺手消掉嵌入扰动。

### 6.5 防止负幅度：截断与补偿

实际代码还处理了"`n2` 被截断到 0"的情况：

```python
n1 = max(m1 + shift, 0)
n2 = max(m2 - shift, 0)
deficit = want - (n1 - n2)
n1 = max(n1 + max(deficit, 0), 0)
n2 = max(n2 + max(-deficit, 0), 0)
```

正常情况下 `D ≤ 1.8 m̄` 已经保证 `n2 > 0`，这段是保险。如果真出现截断，就把差值补到另一侧，尽量维持目标符号。

### 6.6 只改幅度、不改相位

代码：

```python
new1 = n1 * np.exp(1j * np.angle(c1))
new2 = n2 * np.exp(1j * np.angle(c2))
```

`np.angle(c)` 取原相位，`n` 是新幅度。复数的模变了，角度没变。

**为什么**：相位决定条纹的位置。改相位会让边缘错位、出现重影；改幅度只是"这条条纹强一点/弱一点"，视觉上更自然。

### 6.7 同步共轭

每改一个 `(u,v)`，都要改它的镜像 `(8-u mod 8, 8-v mod 8)`：

```python
spec[..., cu, cv] = np.conj(new)
```

三对系数的镜像分别是：

| 原位置 | 镜像 |
|---|---|
| (1,2) | (7,6) |
| (2,1) | (6,7) |
| (2,3) | (6,5) |
| (3,2) | (5,6) |
| (1,3) | (7,5) |
| (3,1) | (5,7) |

这些位置互不重叠，`validate_pairs()` 会检查。如果不改镜像，逆变换出来是复数，取实部会引入额外失真。

### 6.8 IDFT 与回填

```python
out = np.real(np.fft.ifft2(spec, axes=(2, 3)))
```

然后：

```
from_blocks → 拼回平面 → clip(0,255) → 放回 YCrCb 的 Y → 转 BGR → rint → uint8
```

**为什么 clip**：修改后的像素可能略超出 0–255，比如 −0.3 或 255.4。不 clip 的话 `astype(uint8)` 会回绕（−0.3 变成 255），出现严重噪点。

### 6.9 稀疏块怎么跳过

`pipeline.embed()` 构造了一个 `strength_map`：

```python
strength_map = np.zeros(n_blocks)
strength_map[positions] = strength
```

`embed_block_bits()` 里 `strength=0` 的块：

```
target = 0 × base = 0
delta = min(0, 0.9m) = 0
active = False
n1 = m1, n2 = m2
```

所以未选中的块**一个系数都不改**。这就是稀疏嵌入的实现方式。

### 6.10 lena 实测：改动到底有多大

| 指标 | 数值 |
|---|---|
| B̄ | 41.52 |
| α·B̄ | 49.82 |
| 最大像素差 | 19 级 |
| 平均像素差 | 约 0.25 级 |
| 发生变化的像素 | 14.6% |
| 其中只变 1 级 | 9.2% |
| 变 2 级 | 3.3% |
| 变 3 级及以上 | 约 2.1% |
| PSNR | 49.93 dB |
| SSIM | 0.9972 |

**为什么只有 14.6% 的像素变了，而不是 25%**：

- 被选中的块占 25%；
- 块内 3 对系数改动后，IDFT 会把影响摊到 64 个像素上，平均每个像素只变 0.25 级；
- 取整后，块内大约一半像素的值没变，另一半变了 1–2 级；
- 25% × 约 58% ≈ 14.5%。

**为什么最大差有 19 级**：少数纹理强的块，`1.8 m̄` 上限没触发，D 接近 49.8，IDFT 后局部像素可能差十几级。但这些点很少（变 15 级以上的只有个位数像素），而且集中在纹理区，人眼不容易注意。

### 6.11 为什么不同图的 PSNR 差这么多

同样是 α=1.2、R=8，五幅图：

| 图像 | PSNR | JPEG Q60 BER | 特点 |
|---|---|---|---|
| lena | 49.93 | 0.2422 | 平滑，中频能量小，D 常被 1.8m̄ 压住 |
| fruits | 50.65 | 0.1953 | 平滑，颜色均匀 |
| baboon | 39.94 | 0.0000 | 纹理极强，中频能量大，D 用满 |
| board | 39.29 | 0.0000 | 文字/边缘多，高频强 |
| butterfly | 40.14 | 0.0156 | 纹理中等 |

**规律**：

- **平滑图**：中频能量小 → `1.8 m̄` 上限把 D 压小 → 改动轻 → PSNR 高；但水印信号也弱，JPEG 一压就容易错。
- **纹理图**：中频能量大 → D 用满 αB̄ → 改动重 → PSNR 低；但信号强，压缩后反而更稳。

这叫**纹理掩蔽（texture masking）**：纹理区人眼容忍度高，可以改重一点；平滑区容忍度低，只能改轻。我们的全局尺度没有做感知掩蔽，所以呈现出"平滑图 PSNR 高但脆弱、纹理图 PSNR 低但稳健"的自然结果。

> 答辩时如果老师问"为什么 lena 50 dB 而 baboon 40 dB"，就用这段回答。不要只说"图不一样"。

### 6.12 PSNR 高不等于绝对看不见

PSNR 是**全图平均**的均方误差。它可以被大面积的小改动"拉高"，但局部仍可能有可见瑕疵。

所以还要看：

- **SSIM**：结构相似度，0.9972 接近 1；
- **最大像素差**：19 级，但只有个位数像素；
- **差异图**：界面上把差值放大 16 倍并上色，能直接看到改动的空间分布；
- **主观观察**：放大到 100% 看平滑区（天空、脸），有没有块状/条纹。

论文里最好同时报 PSNR、SSIM 和差异图，不要只报一个数。

## 7. 提取：从图里把比特读回来

### 7.1 预处理完全一样

提取端必须做和嵌入端**完全相同**的：

1. 补边到 8 的倍数；
2. 转 YCrCb，取 Y；
3. 8×8 分块；
4. 对每块做二维 DFT。

任何一步不一致（比如补边方式不同、颜色空间不同），块网格或系数就会错位，水印读不出来。

### 7.2 软信息公式

对每个块：

```
local = 六个选中系数幅值的平均
diff_i = |C(p1_i)| - |C(p2_i)|      （第 i 对）
L_block = (diff_1 + diff_2 + diff_3) / 3 / local
```

代码：

```python
local = mean(|C| over 6 coords) + 1e-9
diffs = [|C(p1)| - |C(p2)| for each pair]
soft = mean(diffs) / local
```

- `soft > 0`：倾向 bit 1；
- `soft < 0`：倾向 bit 0；
- `|soft|` 越大：越有把握。

### 7.3 为什么要除以 `local`

`local` 是这个块六个选中系数幅值的平均，代表块的局部能量。

除以它有两个好处：

**（1）跨图可比**：亮图/暗图、纹理强/弱的图，系数幅值整体差很多；归一化后，软信息的量纲大致在 ±1.2 左右，方便统一看置信度。

**（2）抵抗亮度和对比度变化**：

- **亮度偏移**：所有像素加常数 `c`。DFT 里只有 DC `(0,0)` 会变，AC 系数不变。我们选的都不是 DC，所以 `diff` 和 `local` 都不变，软信息不变。实测 ±20 级亮度，BER 全 0。
- **对比度缩放**：`f' = a·f + b`。AC 系数整体乘 `a`，`diff` 和 `local` 都乘 `a`，比值不变。实测对比度 1.05，BER 0。

这就是为什么这两种攻击对水印几乎无影响——**相对幅度规则天生对线性亮度变换免疫**。

### 7.4 重复合并

```python
soft = gather_soft(soft_blocks[positions], n_bits, repeat)
```

把每个比特的 R 个副本（以及块内 3 对的平均）再取平均：

```
L_j = (1/R) Σ(r=0..R-1) L_block(positions[r·n + j])
```

R=8 时，噪声标准差降到 1/√8。

### 7.5 硬判决

无编码方案（`NoCodec`）：

```python
bits = (soft > 0).astype(uint8)
```

正数判 1，负数判 0。简单、可解释。

有编码方案（未来的 Polar）不直接硬判，而是把软信息当 LLR 送进 SC 译码器——这正是 `codes.Codec` 接口按"软信息"设计的原因。

### 7.6 提取端需要知道什么

| 必须知道 | 为什么 |
|---|---|
| 图像尺寸/补边规则 | 块网格要对齐 |
| 块大小 8 | 分块方式一致 |
| 系数对 | 读哪几个系数 |
| 载荷比特数 `n_bits` | 算 `repeat` 和选块数 |
| `max_repeat` | 算 `repeat` |
| 种子 `seed` | 选块位置一致 |
| 是否编码、码型 | 决定怎么译码 |

**不需要知道**：

- 嵌入强度 α（只影响符号，不影响位置）；
- 原始图像（提取是"盲"的，不需要原图）；
- 嵌入时每块的局部能量。

### 7.7 从原图提取会怎样

如果图里根本没有水印，用同样的规则去读：

| 图像 | 从原图提取的 BER |
|---|---|
| lena | 0.5078 |
| baboon | 0.4609 |
| fruits | 0.4531 |

大约 0.45–0.51，也就是**接近随机猜**。这证明：水印不是"图里本来就有"的，是嵌入后才出现的。

### 7.8 软信息长什么样

lena 含水印图：

```
软信息平均幅度：1.2111
软信息均值：-0.2080
正值比例：0.414（= 载荷中 1 的比例 53/128）
最小/最大：-1.651 / 1.552
```

**为什么平均幅度约 1.2**：因为每个系数对的目标差是 `αB̄`，除以 `local ≈ B̄`，得到约 α = 1.2。三对平均后仍然是 1.2。

**为什么均值是负的**：载荷有 53 个 1、75 个 0，0 比 1 多，所以负值多。理论上均值 ≈ α(2p−1) = 1.2 × (2×0.414−1) = −0.206，实测 −0.208，几乎完全吻合。这说明提取逻辑是对的。

### 7.9 为什么提取不需要 α

判决只看符号：

```
bit = 1 if soft > 0 else 0
```

α 只决定"差多大"，不决定"差往哪边"。所以提取端不需要知道 α。这也是相对幅度规则的一个好处：**嵌入强度可以变，提取规则不变**。

### 7.10 提取的复杂度

512×512、128 bit、R=8：

- 4096 个 8×8 块，FFT 很小；
- 只读 1024 个块的软值；
- 实测约 9 ms（本机），完全够界面实时用。

## 8. 攻击模拟：图片在现实中会遭什么罪

### 8.1 "攻击"不是黑客攻击

这里的攻击指**图像处理**：压缩、加噪、滤波、调亮、裁剪、缩放。水印要在这些处理后还能读出来，才算鲁棒。

### 8.2 每种攻击对 DFT 系数的影响

| 攻击 | 代码 | 对系数的影响 | 水印为什么能/不能活 |
|---|---|---|---|
| **JPEG 压缩** | `attacks.jpeg` | 8×8 DCT 量化，高频/小幅系数被清零 | 我们的中频系数幅值较大，部分能活；质量越低死得越多 |
| **高斯噪声** | `gaussian_noise` | 白噪声铺满所有频率 | 噪声幅度小于 D 时不影响符号；重复平均进一步压噪 |
| **高斯模糊** | `gaussian_blur` | 低通，中高频被衰减 | 3×3 轻，5×5 开始伤到中频 |
| **中值滤波** | `median_blur` | 非线性，边缘/纹理被平滑 | 3×3 影响中等 |
| **亮度偏移** | `brightness` | 只改 DC，AC 不变 | 完全不影响（相对幅度） |
| **对比度缩放** | `contrast` | AC 整体乘因子 | 完全不影响（比值不变） |
| **裁剪填充** | `crop_fill` | 挖掉一块，块内像素变常数 | 只影响局部块；交织 + 重复让每个比特只损失少数副本 |
| **缩放往返** | `rescale` | 重采样低通 + 网格重新对齐 | 0.75× 往返后网格回到原尺寸，影响有限 |

### 8.4 为什么亮度/对比度完全不影响

数学上：

```
亮度：f'(x) = f(x) + c
      DFT: C'(u,v) = C(u,v) + c·64·δ(u,v)
      只有 (0,0) 变，AC 不变

对比度：f'(x) = a·f(x) + b
      DFT: C'(u,v) = a·C(u,v)   (u,v) ≠ (0,0)
      |C1'| - |C2'| = a(|C1| - |C2|)
      local' = a·local
      软信息 = 差值/局部能量 = 不变
```

实测亮度 ±20 级，攻击 PSNR 只有 22 dB（图已经明显变亮/变暗），但 BER 仍然是 0。**这说明"图像质量"和"水印存活"是两回事**。

### 8.5 为什么 JPEG 最狠

JPEG 的流程：

```
8×8 分块 → DCT → 除以量化表 → 取整 → 熵编码
```

量化表对高频用很大的步长，很多高频系数直接变成 0。我们的中频系数虽然比高频抗压，但：

- Q60/Q50 时量化步长已经很大；
- 平滑图的中频系数本来就不强，容易被量化到 0 或严重失真；
- 8×8 DFT 和 8×8 DCT 不是同一个变换，量化误差不能完全对齐。

所以 JPEG 是当前最需要纠错码的攻击。Q60 平均 BER 0.0906，约 11.6/128 个比特错——文本已经明显乱码。

### 8.6 为什么裁剪 20% 还 BER=0

三个原因叠加：

1. **重复 8 次**：每个比特有 8 份；
2. **交织**：裁剪区域的块分散到很多不同的比特，每个比特最多损失 1–2 份；
3. **剩余副本还在**：平均后符号不变。

但注意：裁剪 20% 的攻击 PSNR 只有 21.27 dB，图已经缺了一大块。**水印还在，不代表图还能看**。

### 8.7 为什么缩放 0.75× 往返还 BER=0

`rescale` 是"先缩小到 75%，再放大回原尺寸"。虽然重采样会低通、会损失细节，但：

- 最终尺寸回到原尺寸，8×8 网格重新对齐；
- 0.75× 的缩小比例不算极端，中频系数还能保留；
- 重复合并把局部误差压下去。

如果缩放比例更小（比如 0.3×），或者缩放后不回到原尺寸，网格失同步，BER 会明显上升。**当前实验没有覆盖这种失同步场景**，这是局限之一。

### 8.8 单图差异：平均值会骗人

5 图平均 Q60 BER 是 0.0906，但单图：

| 图像 | PSNR | Q60 BER | 文本还能读吗 |
|---|---|---|---|
| lena | 49.93 | 0.2422 | 不能，明显乱码 |
| fruits | 50.65 | 0.1953 | 不能 |
| baboon | 39.94 | 0.0000 | 能，完全正确 |
| board | 39.29 | 0.0000 | 能 |
| butterfly | 40.14 | 0.0156 | 基本能 |

**答辩时不要只报平均值**。老师如果问"Q60 到底行不行"，正确回答是："取决于图像纹理。平滑图 Q60 已经不行，纹理图还行；平均值 0.09，但方差很大。这正是我们要加纠错码的原因。"

### 8.9 "攻击 PSNR"是什么

界面底部有一个"攻击 PSNR"，它是：

```
PSNR(含水印图, 攻击后的图)
```

衡量的是**攻击本身把图破坏了多少**，不是水印质量。比如亮度 +20 的攻击 PSNR 22 dB，说明图已经明显变了；但 BER 仍是 0，说明水印对这种变化免疫。

### 8.10 没做的攻击

- **旋转、平移、透视**：会让 8×8 网格失同步，当前方案不抵抗。
- **真正的裁剪后重拼接**：当前 `crop_fill` 是"挖洞填色"，尺寸不变，不涉及重采样和网格错位。
- **打印-扫描、拍照**：涉及几何、颜色、摩尔纹，远超当前范围。
- **视频压缩**：只做图像，不做视频。

这些要写进论文"局限与展望"，不要回避。

## 9. 评价指标

### 9.1 PSNR：峰值信噪比

```
MSE = (1/N) Σ (原图 - 测试图)²
PSNR = 10 · log10(255² / MSE)   （dB）
```

- 完全相同：MSE=0，PSNR=∞。
- 差得越多：MSE 越大，PSNR 越小。

**dB 的直觉**：

| PSNR | RMSE（灰度级） | 主观感受 |
|---|---|---|
| 30 dB | 8.07 | 明显能看出差别 |
| 35 dB | 4.53 | 仔细看能看出 |
| 40 dB | 2.55 | 不太容易看出 |
| 44 dB | 1.61 | 很难看出 |
| 50 dB | 0.81 | 基本看不出 |

我们的 5 图平均 43.99 dB，lena 49.93 dB，属于"很难看出/基本看不出"。

**PSNR 的局限**：它只看逐像素差的平方，不考虑人眼对结构、边缘、纹理的敏感度。两张 PSNR 相同的图，主观质量可能差很多。所以要配 SSIM。

### 9.2 SSIM：结构相似度

SSIM 不看单个像素，而是看局部窗口里的：

- 亮度（均值）是否接近；
- 对比度（方差）是否接近；
- 结构（协方差）是否接近。

简化公式（每个局部窗口）：

```
SSIM = [(2μxμy + C1)(2σxy + C2)] / [(μx² + μy² + C1)(σx² + σy² + C2)]
```

- `μx, μy`：两个窗口的均值；
- `σx², σy²`：方差；
- `σxy`：协方差；
- `C1 = (0.01×255)²`，`C2 = (0.03×255)²`，防止分母为 0。

代码用 11×11 高斯窗（σ=1.5），对全图每个位置算 SSIM，再取平均。彩色图先转灰度。

- SSIM = 1：完全一样；
- SSIM 越接近 1 越好；
- 我们的 0.9952（平均）/ 0.9972（lena）。

### 9.3 BER：误码率

```
BER = 错误比特数 / 总比特数
```

- 0：全对；
- 0.5：等于瞎猜；
- 1：全反（实际很少见）。

128 bit 载荷下，错 1 个 bit 就是 BER = 1/128 = 0.0078。所以 BER 0.0906 约等于错 11.6 个 bit——平均意义下，单图可能是 0 个、10 个、31 个。

**0.5 的统计涨落**：如果真是随机猜，128 bit 的 BER 标准差是：

```
σ = sqrt(0.25 / 128) ≈ 0.044
```

所以 0.45–0.55 都可能是"随机猜"的正常波动。不要看到 0.46 就说"还有 54% 读对了"。

### 9.4 NC：归一化相关

把 0/1 映射到 −1/+1，再算相关系数：

```
a_i = 2·bit_i - 1
b_i = 2·bit'_i - 1
NC = Σ(a_i·b_i) / sqrt(Σa_i² · Σb_i²)
```

- 1：完全一致；
- 0：不相关；
- −1：完全相反。

对二进制比特，`|a_i|=|b_i|=1`，所以分母是 n，NC 和 BER 有精确关系：

```
NC = 1 - 2·BER
```

验证：Q60 BER 0.09062 → NC = 1 − 0.18124 = 0.81876，表里是 0.81875。完全吻合。

**所以 NC 和 BER 是同一个信息的两种写法**，论文里报一个就够，另一个可以作为交叉验证。

### 9.5 四个指标怎么配

| 指标 | 衡量什么 | 好坏 | 我们的值 |
|---|---|---|---|
| PSNR | 不可见性（逐像素） | 越高越好 | 43.99 dB（均值） |
| SSIM | 不可见性（结构） | 越接近 1 越好 | 0.9952 |
| BER | 提取可靠性 | 越低越好 | 0（无攻击）/ 0.09（Q60） |
| NC | 提取可靠性（相关） | 越接近 1 越好 | 1 / 0.82 |

**前两个看"藏得好不好"，后两个看"读得准不准"**。只报 PSNR 不报 BER，等于只说了一半。

### 9.6 指标不能只看平均

5 图平均 Q60 BER 0.0906，但 lena 0.2422、baboon 0。平均值把"能用的图"和"不能用的图"混在一起了。

论文里建议：

- 报平均值；
- 报最差图；
- 报每幅图的表；
- 画 BER 随攻击强度变化的曲线。

### 9.7 攻击 PSNR 和载体 PSNR 别混

- **载体 PSNR**：含水印图 vs 原图 → 衡量水印不可见性；
- **攻击 PSNR**：攻击后图 vs 含水印图 → 衡量攻击破坏程度。

界面底部两个都显示了，答辩时要说清楚是哪一个。

## 10. 去水印：真的把水印抹掉

### 10.1 目标

让提取端**读不出**原来的载荷，同时尽量不破坏图像。

注意：不是"恢复原图"——没有原图，信息论上不可能精确恢复。我们做的是**破坏水印的检测信号**。

### 10.2 需要什么

`pipeline.remove()` 需要：

- 载荷比特数 `n_bits`；
- `max_repeat`；
- 种子 `seed`；
- 系数对、块大小。

**不需要**：

- 原始图像；
- 嵌入强度 α；
- 嵌入时的局部能量。

所以它是**密钥辅助的去除**，不是"拿原图减一下"的非盲方法。

### 10.3 算法

对每个"嵌入时用过的块"：

```
对每一对系数：
    m1 = |C1|, m2 = |C2|
    mean = (m1 + m2) / 2
    n1 = mean, n2 = mean        ← 把差值拉平到 0
    相位保持不变
    共轭镜像同步
IDFT → 回填 → 取整
```

代码 `flatten_pair_differences()`：

```python
mean = 0.5 * (m1 + m2)
n1 = np.where(mask, mean, m1)
n2 = np.where(mask, mean, m2)
new1 = n1 * np.exp(1j * np.angle(c1))
new2 = n2 * np.exp(1j * np.angle(c2))
```

### 10.4 为什么能抹掉

嵌入时：

```
n1 = m̄ + D/2
n2 = m̄ - D/2
差值 = D（符号 = 比特）
```

去除时把两个都设成 `m̄`：

```
差值 = 0
```

符号信息没有了。提取端再算 `|C1| - |C2|`，理论上得到 0，判决 `soft > 0` 就变成随机（实际由取整残差决定）。

### 10.5 为什么去水印后 PSNR 反而更高

设原始自然差值是 `d0`（通常很小），嵌入后是 `±D`（通常远大于 `d0`），去除后是 0。

```
含水印图与原图的差：|±D - d0| ≈ D
去除图与原图的差：  |0 - d0| = |d0|
```

因为 `|d0| < D`，去除图在系数空间里**比含水印图更接近原图**。

再加上嵌入时保持了中点 `m̄`，去除只是把差值归零，中点没变，所以嵌入引入的主要扰动被消掉了。

实测：

| 图像 | 含水印 PSNR | 去水印 PSNR | 提升 |
|---|---|---|---|
| lena | 49.93 | 51.68 | +1.75 dB |
| baboon | 39.94 | 42.68 | +2.74 dB |
| fruits | 50.65 | 52.08 | +1.43 dB |
| board | 39.29 | 42.13 | +2.84 dB |
| butterfly | 40.14 | 40.90 | +0.76 dB |

**但这不是"恢复原图"**：原始的自然差值 `d0` 也被抹成 0 了。PSNR 更高只是因为嵌入扰动比自然差值大。

### 10.6 为什么 BER 不是精确的 0.5

按理论，差值拉平后应该是 0，判决随机，BER=0.5。实测：

| 图像 | 去水印后 BER | 去除后软信息平均幅度 | 嵌入时软信息幅度 |
|---|---|---|---|
| lena | 0.2891（37/128） | 0.0488 | 1.2111 |
| baboon | 0.5625（72/128） | 0.0054 | 约 1.2 |
| fruits | 0.2344（30/128） | 0.0717 | 约 1.2 |
| board | 0.2578（33/128） | 0.0422 | 约 1.2 |
| butterfly | 0.2109（27/128） | 0.0669 | 约 1.2 |

原因有三层：

**（1）uint8 取整会"保留"一部分水印**

去除是在浮点 DFT 域做的，但最后要存回 uint8。含水印图本身就是取整后的；去除图的值和它很接近，四舍五入后**很多像素会落回原来的整数值**，于是残留的差值仍然和嵌入符号弱相关。

- 平滑图（lena、fruits）：D 被 `1.8m̄` 压得小，去除时移动量小，取整更容易"保留"原值 → 残留软信息大（0.05–0.07），BER 偏低（0.21–0.29）。
- 纹理图（baboon）：D 大，去除时移动量大，取整保留得少 → 残留软信息极小（0.005），BER 接近 0.5。

**（2）128 bit 样本太小**

随机情况下 BER 的标准差约 0.044。0.56 或 0.44 都可能是正常波动。

**（3）载荷本身有偏置**

载荷中 1 占 41.4%。如果检测器偏向输出 0，BER 会低于 0.5（例如全判 0 时 BER=0.414）。所以 0.289 不等于"还有 71% 读对了"，它混合了"残留相关"和"判决偏置"。

**正确的答辩说法**：

> 去水印后 BER 在 0.21–0.56 之间，软信息幅度从 1.2 降到 0.005–0.07，文本已经完全乱码。没有到精确 0.5，是因为 uint8 取整残留和 128 bit 小样本统计涨落；这不代表水印还能读，只代表检测器还有一点点弱相关。

**不要做的错误解释**：不要说"BER 0.289 说明还有 71% 的水印没去掉"。BER 不是"保留比例"。

### 10.7 这算"盲"还是"非盲"

文献里的定义：

- **盲水印（blind）**：检测/提取不需要原始宿主图像。
- **非盲水印（non-blind）**：需要原始宿主图像。

我们的提取**不需要原图**，所以从宿主角度是盲的；但去除需要**密钥/嵌入参数**。严格说：

> 这是"已知密钥的盲去除"（key-assisted blind removal），不是利用原图的非盲方法。

之前 `docs/design.md` 曾把这里写成"非盲去除"，那是指"知道密钥"，不是文献里的严格定义；现已改为"已知密钥的盲去除"。答辩时按上面的说法更准确。

### 10.8 没有密钥能不能去

理论上可以"盲扫"：

- 把**所有** 4096 个块的系数对都拉平；
- 这样不管水印写在哪，都会被破坏。

但代价：

- 改了 4 倍的块，图像失真更大；
- 破坏了所有自然系数对的关系，PSNR 更低；
- 提取端如果换种子，仍然可能读到别的残留。

这是"删水印"攻击，不是"高质量去除"。我们的演示假设操作者知道密钥，属于版权方/授权方场景。

### 10.9 信息论上不可逆

嵌入是多对一映射：

```
原图 + 比特 → 含水印图
```

很多不同的原图/比特组合可能得到同一张含水印图。没有额外信息，无法唯一恢复原图。去水印只能"破坏检测信号"，不能"还原原始像素"。

### 10.10 演示时怎么说

1. 先点"提取信息"，显示原文本和 BER 0；
2. 点"去水印"，显示去除图；
3. 再点"提取信息"（或看界面自动算的再提取 BER），显示乱码和 BER 0.29；
4. 说："水印信号已经被破坏，文本不可读；PSNR 反而更高，是因为嵌入扰动被消掉了。"

## 11. 参数决策：为什么是这些数

### 11.1 参数总表

| 参数 | 取值 | 一句话理由 |
|---|---|---|
| 块大小 | 8×8 | 和 JPEG 对齐；容量/频率分辨率的折中 |
| 系数对 | (1,2)/(2,1)、(2,3)/(3,2)、(1,3)/(3,1) | 等半径、中频、三对平均降噪 |
| 嵌入强度 α | 1.2 | PSNR 约 44 dB，Q60 BER 约 0.09，给纠错码留空间 |
| 重复次数 R | 8 | 只用 25% 块，PSNR +5 dB，Q80 接近 BER 0 |
| 尺度基准 | 全图平均（global） | 比逐块局部高约 2 dB（当前复测；旧版约 3 dB） |
| 选块种子 | 2027 | 可复现 + 访问控制 |
| 载荷 | 128 bit（16 字节） | 短文本；二值 32×32 自动降到 R=4 |
| 纠错码 | (256,128) Polar（计划） | 码率 1/2，128 信息位直接对应载荷 |

### 11.2 每个参数的理由

**块大小 8×8**

- 与 JPEG 的 8×8 网格对齐，压缩时不会网格错位。
- 4×4：块数翻倍、容量翻倍，但中频系数太少（只有 (1,1)、(1,2)、(2,1) 等），三对都凑不齐，鲁棒性差。
- 16×16：频率分辨率更高，但块数只有 1/4，容量下降；一块被破坏影响更大；和 JPEG 网格也不再一一对应。

**系数对**

- 半径 2.24 / 3.61 / 3.16，都在中频。
- 低频（DC、1,1）改了就看得见；高频（3,3 以上）一压缩就没。
- 三对在同一个块里承载同一个比特，相当于块内 3 次重复；提取时平均，降低单对噪声。
- 必须是等半径，否则自然幅值差会压过水印（见 3.8）。

**α=1.2**

`scripts/grid_search.py` 的结果（5 图均值，当前环境复测）：

| α | R | PSNR | Q70 | Q60 | Q50 | 模糊 5×5 |
|---|---|---|---|---|---|---|
| 0.8 | 8 | 44.95 | 0.067 | 0.130 | 0.152 | 0.155 |
| **1.2** | **8** | **43.99** | **0.036** | **0.091** | **0.119** | **0.103** |
| 1.6 | 8 | 43.13 | 0.017 | 0.064 | 0.100 | 0.077 |
| 1.2 | 16 | 40.90 | 0.009 | 0.030 | 0.062 | 0.037 |
| 2.0 | 16 | 39.34 | 0.000 | 0.009 | 0.036 | 0.020 |

- α 越大，越稳，PSNR 越低。
- α=1.2 是"PSNR 还能看、Q60 还没完全崩"的折中点。
- 如果只追求鲁棒性，α=2.0、R=16 更好，但 PSNR 只有 39.3 dB，且用了更多块。
- `README.md` 与 `docs/design.md` 已同步为当前环境（OpenCV 5.0）的数值，原始数据在 `results/summary_20261110_233652.csv`；`results/summary_20261101_202704.csv` 仍是 2026-11-01 旧环境的结果（44.06 / 0.078），趋势一致、绝对值略有差异。

**R=8**

- 写满全图（R=32）PSNR 约 39 dB；R=8 约 44 dB，高 5 dB 多。
- R=8 时 Q80 仍接近 BER 0，Q70 开始少量错，Q60 明显错。
- R 再小（4）画质更好，但 Q70 就开始错；R 再大（16）更稳，但 PSNR 掉到 41 dB。
- 8 是"画质/鲁棒性/容量"的平衡点。

**global 尺度**

| 尺度基准 | PSNR | 最低 PSNR | Q70 | Q60 | 模糊 5×5 |
|---|---|---|---|---|---|
| local（块内） | 42.28 | 37.44 | 0.052 | **0.075** | 0.188 |
| geometric（几何平均） | 43.63 | 39.03 | 0.052 | 0.087 | 0.138 |
| **global（全图）** | **44.23** | **39.59** | **0.036** | 0.098 | **0.119** |

- 逐块定强度：纹理块的中频能量大，D 也大，失真集中在这些块；PSNR 按全图 MSE 算，被这些块拉低。
- 全图定强度：每块 D 一样，失真更均匀，PSNR 比 local 高约 **2 dB**。
- 代价：同 α 下，global 的 JPEG Q60 反而略差（0.098 vs local 0.075），因为 local 会把纹理块的信号加强，纹理块恰好更抗 JPEG；但 global 的 Q70 和 5×5 模糊更好。
- 结论：**global 胜在画质稳定、Q70 和模糊；如果只盯 JPEG Q60，local 也是一个合理选择。** 我们默认 global，是为了让不同图的 PSNR 更可控、参数解释更简单。

**种子 2027**

- 只是可复现的随机种子；换成别的数也能工作。
- 它的作用是"选块排列"，让不知道种子的人对不准位置。
- 不是加密，别夸大。

**128 bit**

- 16 字节文本，够写"DEMO 水印 2027"这类标识。
- 二值 32×32 需要 1024 bit，512×512 图上 R 自动降到 4，仍能嵌入，但鲁棒性下降。
- 要更大的载荷，需要更大图像、更低重复，或者接受更差画质。

### 11.3 三角权衡的具体体现

| 你想要 | 代价 |
|---|---|
| 更大容量 | 用更多块 / 降低 R → 画质差、易错 |
| 更好画质 | 降低 α / 减少块 → 鲁棒性差 |
| 更强鲁棒性 | 提高 α / 增加 R → 画质差、容量小 |
| 更强安全性 | 更大种子空间 / 加密 → 实现复杂 |

**没有免费午餐**。论文的贡献不是"三项都最好"，而是"在给定画质下，把鲁棒性做到可接受，并给出可复现的参数依据"。

### 11.4 如果老师让你改参数

- **"能不能更清楚？"** → 降低 α 到 0.8，PSNR 升到约 45 dB，但 Q60 BER 升到约 0.13。
- **"能不能更抗压缩？"** → 提高 α 到 1.6 或 R 到 16，Q60 BER 降到 0.02–0.06，但 PSNR 降到 41–43 dB。
- **"能不能多藏点？"** → 换 1024×1024 图，或用二值 32×32 + R=4；或者接受更低的 R。
- **"能不能更快？"** → 降 R、缩小图像；当前 512×512 嵌入约 41 ms，提取约 9 ms，已经很快。

## 12. Polar 码与 SC 译码（论文下一阶段）

> 这一章是"计划"，不是"已完成"。答辩时务必区分。

### 12.1 为什么需要纠错码

Q60 平均 BER 0.0906，128 bit 里约 11.6 个错。文本是定长字节，错一个 bit 就可能让一个汉字变成乱码；错十几个，整段文本就废了。

重复 8 次只能把**随机噪声**压下去；但 JPEG 的错误是**系统性**的：某些块/某些频率就是被量化掉了，重复再多，如果 8 份都被同样地破坏，平均也救不回来。

纠错码的思路：**在写入前加冗余，让接收端能发现并纠正错误**。

### 12.2 基本概念

| 名词 | 含义 |
|---|---|
| 码长 n | 编码后的比特数 |
| 信息位 k | 原始信息比特数 |
| 码率 R = k/n | 信息占的比例；1/2 表示一半是冗余 |
| 编码 | k 个信息 bit → n 个编码 bit |
| 译码 | n 个带噪观测 → k 个信息 bit |
| 纠错能力 | 能纠正多少个错误（取决于码和译码算法） |

(256,128) 码：k=128，n=256，码率 1/2。128 bit 载荷 → 256 bit 编码 → 需要 256×R 个块。

### 12.3 Polar 码的核心

Polar 码（Arikan, 2009）的核心是**信道极化**：

- 把 n 个相同的信道，通过线性变换组合成 n 个"合成信道"；
- 当 n 增大时，一部分合成信道变得**几乎完美**，另一部分变得**几乎无用**；
- 把信息放在"好"的信道上，把"坏"的信道固定成 0（冻结位）。

编码结构：

```
F = [[1, 0],
     [1, 1]]

G = F^(⊗n) · B
x = u · G
```

- `F^(⊗n)` 是 F 的 n 次 Kronecker 幂；
- `B` 是比特反序置换；
- `u` 是长度 n 的向量，信息位 + 冻结位；
- `x` 是编码后的 n 个比特。

2×2 的 F 就是：

```
x0 = u0 ⊕ u1
x1 = u1
```

也就是"把信息一步步异或到前面的位上"，产生冗余。

### 12.4 冻结位怎么选

常用两种：

- **Bhattacharyya 上界**：算每个合成信道的 Bhattacharyya 参数，选最小的 k 个。
- **高斯近似（GA）**：假设信道是 AWGN，递归计算每个比特信道的 LLR 均值，选最大的 k 个。

本项目的 `PolarCode` 预留了 `design_snr_db=2.0`，计划用高斯近似离线算好冻结位集合，写成常量。这样运行时不用每次重新构造。

### 12.5 SC 译码

SC（Successive Cancellation，逐次消除）：

- 从第 0 位开始，一位一位判；
- 判完当前位，就用它去帮助后面的位；
- 遇到冻结位，强制判 0；
- 遇到信息位，根据 LLR 的符号判 0/1。

两个基本的 LLR 递推：

```
f(a, b) = 2·atanh( tanh(a/2)·tanh(b/2) )
        ≈ sign(a)·sign(b)·min(|a|, |b|)      （常用近似）

g(a, b, u) = b + (1 - 2u)·a
```

`f` 用于"两个观测合起来看前一位"，`g` 用于"已知前一位后看后一位"。递归下去就是一叉树。

### 12.6 本系统的参数

- (N, K) = (256, 128)，码率 1/2；
- 信息位 128，正好对应 16 字节文本；
- 冻结位 128，固定 0；
- SC 译码，输入是提取端的软信息（乘以缩放因子 ρ 作为 LLR）。

### 12.7 公平对比怎么设计

基线（无编码）：

```
128 bit × R=8 = 1024 个块
```

Polar：

```
256 bit × R=4 = 1024 个块
```

**总块数、载荷、攻击条件相同，只改编码层**。这样 BER 的改善才能归因于纠错码，而不是"多用了块"或"改得更重"。

如果坚持 R=8，Polar 要用 2048 个块（50% 的图），画质会更差，对比不公平。

> 这是答辩时容易被问的点：**"你用 Polar 是不是因为多写了块？"** 正确回答：公平对比固定总块数，Polar 的 R 降到 4，用纠错增益补偿副本减少。

### 12.8 LLR 缩放 ρ

我们的软信息量纲不是标准 LLR（大约 ±1.2），而 SC 期望的是对数似然比。通常乘一个正数 ρ 来匹配。

**重要**：纯 SC 的判决只看 LLR 的符号，所有 LLR 同乘一个正数，符号不变，判决也不变。所以 ρ 不影响"理想 SC"的硬判决；它主要影响：

- 数值稳定性（避免溢出/下溢）；
- 如果加 CRC 或做软输出，ρ 会影响度量；
- 与信道模型匹配时，理论分析更方便。

> "当前完成的是无编码基线，嵌入、提取、攻击、指标、去水印、界面都跑通了。Polar 码是开题报告里写的下一阶段：固定 (256,128)、高斯近似选冻结位、SC 译码，接口已经按软信息设计好。公平对比会固定总块数，基线 128×8=1024，Polar 256×4=1024，只改编码层。目前还没有编码增益的实验数据，不能提前下结论。"

```
       └─ codec.decode(soft)                    # 硬判决 / Polar
```

### 13.5 `remove` 调用链

```
gui.on_remove()
  └─ pipeline.remove(target, n_bits, codec, max_repeat, seed)
       ├─ fit_to_blocks + _to_plane
       ├─ count_blocks + plan_layout
       ├─ flatten_pair_differences(plane, positions)
       │    ├─ to_blocks + fft2
       │    ├─ 每对：m1=m2=mean
       │    ├─ 保相位、共轭
       │    └─ ifft2 + from_blocks
       └─ _from_plane
```

### 13.6 界面状态机

```
orig ──加水印──► wm ──攻击──► attacked
                  │              │
                  │              ├──提取信息──► extracted
                  │              └──去水印────► removed ──再提取──► BER↑
                  └──────── 未攻击时直接对 wm 提取/去除 ────────┘
```

关键规则：

- `orig` 为空 → "加水印"禁用；
- `wm` 为空 → "提取信息/去水印/攻击/保存"禁用；
- 加水印时把 `(codec, max_repeat, seed)` 存进 `embed_params`；
- **提取和去水印一律用 `embed_params`**，不用界面当前控件的值，防止用户事后改参数导致选块错位；
- 攻击结果存 `attacked`，不覆盖 `wm`；
- 去水印结果存 `removed`，不覆盖 `wm`；
- "保存图片"：有去除结果就存去除图，否则存含水印图。

## 14. 答辩问答

> 下面每个回答都尽量短，先给结论，再给理由。真正的答辩不需要背全文，记住加粗的那句就行。

### Q1. 为什么用 DFT，不用 DCT 或 DWT？

**因为课题要求 DFT，而且 DFT 的幅度/相位和共轭对称让"只改幅度、保证实图像"这件事很干净。** DCT 也能做水印，JPEG 本身就用 DCT；DWT 更适合多分辨率/几何攻击。我们没有说 DFT 绝对最好，而是在 DFT 域把一套规则做完整、测清楚。

### Q2. 为什么分 8×8 块，不整张图做 DFT？

**为了和 JPEG 的 8×8 网格对齐，并且让局部损坏只影响局部。** 整张图 DFT 频率分辨率高，但一处裁剪会影响全局，还需要同步。8×8 的代价是频率分辨率粗，但换来了鲁棒性和实现简单。

### Q3. 为什么只改亮度 Y？

**人眼对色度细节不如亮度敏感，而且 JPEG 通常对色度下采样。** 写 Y 通道画质更自然，灰度图也能共用一套流程。彩色图往返的额外误差小于 0.1 dB。

### Q4. 为什么必须是等半径系数对？

**半径不同，两个系数的自然能量就差很多，差值符号会被图像内容决定，而不是水印。** 我们实验过 (1,1)/(2,2)，BER 恒为 0.617，怎么调强度都没用。等半径对（如 (1,2)/(2,1)）天生幅值接近，水印才压得住。

### Q5. 为什么只改幅度，不改相位？

**相位承载结构和边缘位置，改相位会出现重影、错位、振铃。** 改幅度只是把某条条纹调强/调弱，视觉上更自然。

### Q6. 为什么要同步修改共轭位置？

**实图像的 DFT 必须满足 C(u,v)=conj(C(8-u,8-v))。** 只改一边，逆变换出来是复数；取实部会引入额外失真。同步改镜像，保证 IDFT 结果是实图像。

### Q7. 为什么用全图平均幅值，不用每块自己的？

**逐块定强度会让纹理块改得过重，拉低全图 PSNR；全图基准在同 α 下 PSNR 高约 2 dB（当前复测；旧版约 3 dB），Q70 和模糊也更好。** 代价是平滑区相对改动更重，且同 α 下 JPEG Q60 不一定更好；绝对改动小，人眼更能接受。

### Q8. 为什么每个比特重复 8 次？

**重复平均能把噪声标准差降到 1/√8，而且一个副本坏了不影响多数。** R=8 只改 25% 的块，PSNR 比写满全图高约 5 dB，Q80 仍然 BER 0。R 再大更稳但画质差，R 再小画质好但 Q70 就错。

### Q9. 为什么块 k 承载比特 k mod n？

**为了交织。** 裁剪会破坏空间上连续的一片块；如果按"连续 8 个块写同一个比特"，一片裁剪可能毁掉几个比特的全部副本。`k mod n` 让被裁剪的块分散到很多不同的比特，每个比特只损失 1–2 份。

### Q10. 种子算加密吗？

**不算。** 它是选块排列的密钥，防的是"不知道规则的人"，不防"拿到代码的人"。商业系统还需要密钥派生、认证、抗逆向。答辩时不要把它说成密码学安全。

### Q11. PSNR 50 dB 是不是太高了，真的看不见吗？

**PSNR 是全图平均，50 dB 对应 RMSE 约 0.8 个灰度级，绝大多数像素只变 1–2 级。** 但少数纹理块最大差 19 级。所以我们同时报 SSIM 0.997、差异图和主观观察，不只看 PSNR。

### Q12. BER 0.5 是什么意思？

**等于瞎猜。** 对 128 bit，随机猜的 BER 标准差约 0.044，所以 0.45–0.55 都可能是随机。不要看到 0.46 就说"还有 54% 读对了"。

### Q13. 去水印后为什么 PSNR 反而更高？

**因为嵌入把系数差拉到了 ±D，去除把它拉回 0，而原始自然差值 d0 通常远小于 D。** 所以去除图在系数空间比含水印图更接近原图。但这不是"恢复原图"——原始的自然差值也被抹掉了。

### Q14. 去水印后 BER 为什么不是精确 0.5？

**uint8 取整会把一部分含水印像素原样保留，残留差值仍与嵌入符号弱相关；128 bit 样本又小，统计涨落大。** 软信息幅度从 1.2 降到 0.005–0.07，文本已经乱码。BER 0.29 不代表"还有 71% 没去掉"。

### Q15. 去水印是盲的还是非盲的？

**提取不需要原图，所以从宿主角度是盲的；但去除需要密钥/嵌入参数。** 严格说是"已知密钥的盲去除"（key-assisted blind removal），不是文献里"需要原图"的非盲方法。

### Q16. 能抵抗旋转、缩放、平移吗？

**不能抵抗旋转和平移，网格会失同步。** 0.75× 缩放往返能过，是因为最终回到原尺寸、网格重新对齐；如果缩放后不回到原尺寸，也会失同步。这是当前方案的明确局限，论文里会写进"展望"。

### Q17. 容量有多大？

**512×512 图裸容量 4096 bit = 512 字节；R=8 时信息容量 512 bit = 64 字节；当前用 128 bit，占 25% 的块。** 二值 32×32 是 1024 bit，R 自动降到 4。要更大容量就换大图或降 R。

### Q18. 实时性怎么样？

**512×512 嵌入约 41 ms，提取约 9 ms，攻击 < 20 ms。** 界面同步执行不卡顿。

### Q19. Polar 码实现了吗？

**没有，当前是接口占位。** 基线已完成；Polar 是下一阶段：固定 (256,128)、高斯近似选冻结位、SC 译码，公平对比固定总块数（基线 128×8，Polar 256×4）。目前没有编码增益数据，不能提前下结论。

### Q20. 你的创新点是什么？

**不是发明新的水印理论，而是把一套 DFT 水印链路做完整、做可复现，并给出几个工程上的明确选择：**

1. 等半径中频系数对 + 相对幅度符号，对亮度和对比度天然免疫；
2. 全图尺度 + 稀疏密钥选块 + 交织，在画质和鲁棒性之间取得可测的平衡；
3. 提取端直接输出软信息，为 Polar/SC 留好 LLR 接口；
4. 密钥辅助的去水印演示，真的把检测信号抹掉，而不是做样子；
5. 库、攻击、指标、界面、脚本、测试一整套，数据可复现。

**Polar 是计划中的扩展，不是已完成的创新。**

### Q21. 和商业水印比怎么样？

**商业系统有感知掩蔽、同步机制、纠错码、抗几何攻击、密钥管理，我们是一个教学/演示级基线。** 我们的价值是把原理走通、把参数和局限讲清楚，不是替代商业产品。

### Q22. 如果图被截图/再拍照还能读吗？

**截图基本保留像素，能读；拍照引入透视、颜色、摩尔纹、压缩，当前方案不行。** 这属于打印-扫描/拍照攻击，超出范围。

### Q23. 为什么 Q60 平均 BER 0.09，但 lena 是 0.24？

**平均值把平滑图和纹理图混在一起了。** 平滑图中频能量小，D 被安全上限压小，信号弱，JPEG 一压就错；纹理图信号强，反而 BER 0。论文里要报单图，不能只报平均。

### Q24. 如果让你改进，先做什么？

**先做 Polar/SC，把 Q60 的 BER 压下去；再做感知掩蔽（按块纹理调 α），改善平滑图的画质/鲁棒性；然后做同步模板，尝试抗旋转/缩放。** 这三步是按"论文工作量/收益"排序的。

1. 人眼对色度不如亮度敏感；JPEG 常对色度下采样；灰度图只有 Y，能共用流程。
2. 与 JPEG 的 8×8 网格对齐；局部损坏只影响局部；避免全局同步。代价是频率分辨率粗。

5. 实图像 DFT 必须共轭对称；不改镜像，逆变换是复数，取实部会失真。
6. `D = s·min(αB̄, 1.8m̄)`：αB̄ 是标准力度，1.8m̄ 是防止负幅度的安全上限。
7. 保持中点就是保持这对系数的总能量，只把能量从一条条纹挪到另一条，画质更自然；去水印回到中点也方便。
8. 第 i 个选中块承载 `i mod n_bits`；取模是为了交织，让局部损坏分散到不同比特。
9. 只有升序，`reshape(R,n)` 的每一列才正好是同一个比特的 R 个副本；不排序提取必错。
10. 归一化后跨图可比；对亮度偏移和对比度缩放免疫（分子分母同比例变化）。
11. 亮度只改 DC，AC 系数不变；我们选的都不是 DC，所以差值不变。
12. 重复 8 次 + 交织，裁剪区域的块分散到很多比特，每个比特只损失 1–2 份，剩余副本平均后符号不变。
13. 嵌入把差值拉到 ±D，去除拉回 0；原始自然差值 d0 通常远小于 D，所以去除图更接近原图。
14. uint8 取整保留了部分含水印像素，残留与嵌入符号弱相关；128 bit 样本小；载荷有偏置。
15. 不算。它是排列密钥/访问控制，不防拿到代码的人；没有密码学密钥派生和认证。
16. 4096 bit = 512 字节；R=8 时 512 bit = 64 字节（当前只用 128 bit）。
17. 平滑图中频能量小，D 被 1.8m̄ 压小，信号弱；纹理图信号强，压缩后更稳。
18. 冻结位是固定为 0、不携带信息的位置；它们对应"坏"的合成信道，用来保护信息位。
19. 否则 Polar 可能因为多用了块/改得更重而获胜，增益不能归因于纠错码。公平对比固定总块数：基线 128×8，Polar 256×4。
20. 不抗旋转/平移/大幅缩放；平滑图鲁棒性不足；Polar 未实现；去水印只能破坏检测信号、不能恢复原图；裁剪是挖洞填充不是真实重采样。（任答三条）

## 18. 一页纸公式卡

```
【DFT】
C(u,v) = Σ_m Σ_n f(m,n) e^(-j2π(um+vn)/8)
f(m,n) = (1/64) Σ_u Σ_v C(u,v) e^(+j2π(um+vn)/8)
共轭：C(u,v) = conj(C((8-u)%8, (8-v)%8))

【嵌入】
m1 = |C1|, m2 = |C2|, m̄ = (m1+m2)/2
D = s · min(α·B̄, 1.8·m̄),  s = +1 (bit1), -1 (bit0)
shift = (D - (m1-m2)) / 2
n1 = m1 + shift, n2 = m2 - shift
C1' = n1·e^(j∠C1), C2' = n2·e^(j∠C2)

【提取】
local = mean(|C| over 6 coords)
L_block = mean(|C(p1)| - |C(p2)| over 3 pairs) / local
L_j = mean over R copies
bit = 1 if L_j > 0 else 0

【去水印】
n1 = n2 = (m1+m2)/2
相位不变，共轭同步

【指标】
PSNR = 10 log10(255² / MSE)
BER = 错误bit / 总bit
NC = 1 - 2·BER   （二进制）
SSIM：11×11 高斯窗，C1=(0.01·255)²，C2=(0.03·255)²

【容量】
块数 = ceil(H/8)·ceil(W/8)
裸容量 = 块数 bit
信息容量 = 块数 / R bit
```
