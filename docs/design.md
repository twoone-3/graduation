# 设计说明与参数决策

本文档记录算法设计与参数选择的依据，可作为论文第 3 章（算法设计）与第 4 章（系统实现）的素材。
数字均来自本工程 `scripts/` 下的实验（5 幅测试图均值，载荷 128 bit）。未特别注明的均为当前环境（Python 3.14 / numpy 2.5 / OpenCV 5.0）复测值；2026-11-01 旧环境的差异在对应表下方注明。

---

## 1. 总体数据流

```
原图 ──► 亮度提取(Y) ──► 8×8 分块 ──► 2D-DFT ──► 中频系数对幅度调制 ──► 2D-IDFT ──► 回填 Y ──► 含水印图
                  ▲                                                                    │
                  │                                                                    ▼
            水印载荷(文本/二值) ──► 比特 ──► Polar 编码 ──► 重复分散(选块密钥) ──► 攻击信道
                                                                                       │
提取图 ──► 亮度提取 ──► 8×8 分块 ──► 2D-DFT ──► 系数对幅值差(软信息) ──► 重复合并 ──► Polar 译码(SC) ──► 比特 ──► 载荷
```

只使用亮度通道的理由：人眼对色度细节的分辨力低于亮度，同等 PSNR 下嵌 Y 通道的主观质量更好；同时灰度图与彩色图可以共用同一套流程。

## 2. 嵌入规则

对每个 8×8 块做二维 DFT：

$$C(u,v)=\sum_{m=0}^{7}\sum_{n=0}^{7} f(m,n)\,e^{-j2\pi(um+vn)/8}$$

取若干**中频、等半径**系数对 $\{(u_1,v_1),(u_2,v_2)\}$，对每个系数对令：

$$\bigl|C(u_1,v_1)\bigr|-\bigl|C(u_2,v_2)\bigr| = s_b\cdot \Delta,\qquad s_b=\begin{cases}+1,& b=1\\ -1,& b=0\end{cases}$$

其中幅度调制量

$$\Delta=\min\Bigl(\alpha\cdot \bar{B},\;0.9\cdot\frac{m_1+m_2}{2}\Bigr),\qquad m_i=|C(u_i,v_i)|$$

$\bar B$ 为**全图**所选系数幅值的均值，$\alpha$ 为嵌入强度。实际实现是保持两系数幅值中点不变、按差值分配调整量：

$$\text{shift}=\tfrac12\bigl(s_b\cdot 2\Delta-(m_1-m_2)\bigr),\quad n_1=m_1+\text{shift},\quad n_2=m_2-\text{shift}$$

相位保持不变（$C'=n\,e^{j\angle C}$），并同步把共轭位置 $C(8-u,8-v)$ 置为共轭值，保证 IDFT 输出为实图像。

### 2.1 为什么必须用"等半径"系数对

自然图像功率谱随频率半径衰减，若系数对的两个位置半径不同（例如 $(1,1)$ 与 $(2,2)$），其固有幅值差往往远大于 $\Delta$，符号由图像内容而非水印决定。

实验中把系数对换成 $(1,1)/(2,2),(1,3)/(3,1),(1,2)/(2,1)$ 后，无论强度取 0.2 还是 0.5、无论攻击轻重，BER 都恒为 **0.617**——典型的"系统性失效"，重复再多也无用。

### 2.2 为什么尺度基准用全图均值而不是局部能量

| 尺度基准 | 强度 | PSNR(均值) | 最低 PSNR | JPEG Q70 | Q60 | 高斯模糊 5×5 |
|---|---|---|---|---|---|---|
| local（块内） | 1.10 | 42.28 | 37.44 | 0.052 | **0.075** | 0.188 |
| geometric（几何平均） | 1.10 | 43.63 | 39.03 | 0.052 | 0.087 | 0.138 |
| **global（全图）** | **1.10** | **44.23** | **39.59** | **0.036** | 0.098 | **0.119** |

同强度下 global 比 local 高约 2 dB：逐块定强度会让纹理/文字图（board、baboon 的中频能量高）过度失真，而 PSNR 是按全图均方误差算的，这些块拉低了整体指标。global 在 Q70 和 5×5 模糊上也更好；但同强度下 Q60 反而略差（0.098 vs 0.075），因为 local 会把纹理块的信号一并加强，而纹理块恰好更抗 JPEG。综合画质稳定性与参数可解释性，默认选 global；代价是平滑区嵌入相对更"重"，不过平滑区绝对改动小、人眼掩蔽也弱。

## 3. 提取规则

对每块同样做 DFT，计算归一化软信息（正数倾向 1）：

$$L_{\text{block}}=\frac{1}{|P|}\sum_{(p_1,p_2)\in P}\frac{|C(p_1)|-|C(p_2)|}{\bar B_{\text{local}}}$$

按"块 $k$ 承载比特 $k \bmod n$"的规则，对每个比特的 $R$ 个副本取算术平均，得到 $L_1,\dots,L_n$。无编码方案直接硬判决 $b_j=[L_j>0]$；Polar 方案把 $L_j$ 乘以缩放因子后作为信道 LLR 输入 SC 译码器。

> 注意：提取端不需要知道嵌入强度 $\alpha$，只需要比特与块的映射关系（即种子）。这是相对幅度规则的一个好处。

## 3.1 去水印规则

去水印与提取共用同一套"块 -> 比特"映射，但目标相反：把每个用过的块里各系数对的幅值**拉平到两者均值**，令

$$\bigl|C(p_1)\bigr|-\bigl|C(p_2)\bigr| \leftarrow 0$$

符号信息因此被抹掉（再次提取时只剩舍入残差决定的正负，软信息幅度从约 1.2 掉到 0.005–0.07，文本已乱码），而两个系数回到原本的能量水平，相位不变、共轭位置同步更新。

实测（lena，128 bit，α=1.2，R=8）：

| 图像状态 | PSNR（相对原图） | 提取 BER |
|---|---|---|
| 含水印 | 49.93 dB | 0.0000 |
| 去水印后 | **51.68 dB** | 0.2891（37/128，文本乱码） |

五幅图去水印后的 BER 在 0.21–0.56 之间，并没有精确等于 0.5：uint8 取整会把一部分含水印像素原样保留，残留差值与嵌入符号仍有弱相关；再加上 128 bit 样本较小，统计涨落本身就约 ±0.044。纹理图（baboon 0.5625）几乎完全随机，平滑图（butterfly 0.2109、fruits 0.2344）残留稍多，但软信息幅度都已降到接近 0，文本不可读。不能把 0.29 解读成"还有 71% 的水印没去掉"。

去除后 PSNR 反而更高，是因为嵌入时把幅值差强制拉到 $\pm\Delta$，而去除只是回到两系数的均值——这一步把嵌入引入的扰动也一并消掉了。需要说明的是，提取本身不需要原图（对宿主是盲的），但去除需要种子/重复次数等密钥参数，因此准确说法是"已知密钥的盲去除"（key-assisted blind removal），而不是文献里依赖原图的非盲方法。

## 4. 参数决策表

| 参数 | 取值 | 依据 |
|---|---|---|
| 块尺寸 | 8×8 | 与 JPEG 变换网格对齐；4×4 容量翻倍但中频系数太少，16×16 抗裁剪更好但定位精度差 |
| 系数对 | (1,2)/(2,1)、(2,3)/(3,2)、(1,3)/(3,1) | 半径 2.24/3.61/3.16，均为中频；每块 3 对取平均可降噪 |
| 嵌入强度 α | 1.2 | grid_search：PSNR 44 dB 下 Q70 误码 3.6%，留出 Polar 的发挥空间 |
| 重复次数 R | 8 | 只写入 1024/4096 块；相比写满全图，PSNR +5 dB，Q80 误码仍接近 0（0.002） |
| 选块种子 | 2027 | 随机选块的密钥；种子不符时 BER 趋于 0.5，起到访问控制作用 |
| 载荷长度 | 128 bit（16 字节文本） | 满足"短文本/二值水印"要求；二值 32×32 图需 1024 bit，应改用更大图像或降低重复次数 |
| 码长/码率 | (N,K)=(256,128) | 固定参数，便于实现与对比；由 128 bit 载荷直接映射 |

### 4.1 强度 × 重复次数（节选，完整见 `scripts/grid_search.py`）

| α | R | PSNR | Q70 | Q60 | Q50 | 模糊5×5 |
|---|---|---|---|---|---|---|
| 0.8 | 8 | 44.95 | 0.067 | 0.130 | 0.152 | 0.155 |
| **1.2** | **8** | **43.99** | **0.036** | **0.091** | **0.119** | **0.103** |
| 1.6 | 8 | 43.13 | 0.017 | 0.064 | 0.100 | 0.077 |
| 1.2 | 16 | 40.90 | 0.009 | 0.030 | 0.062 | 0.037 |
| 2.0 | 16 | 39.34 | 0.000 | 0.009 | 0.036 | 0.020 |

结论：鲁棒性随 α、R 单调变好，PSNR 单调变差；稀疏嵌入（小 R）在"每 dB 换来的鲁棒性"上明显更划算。

> 表中数字为当前环境（Python 3.14 / OpenCV 5.0）复测。2026-11-01 旧环境的结果为 1.2/8：PSNR 44.05、Q70 0.034、Q60 0.078，趋势一致、绝对值略低。

## 5. 容量分析

512×512 图像：块数 $64\times64=4096$，每块 1 bit，裸容量 4096 bit。
当前配置：128 bit 载荷 × 8 次重复 = 1024 块，占用 25% 容量，其余 75% 的块不携带水印。

若改用二值 32×32 图（1024 bit），在 512×512 上只剩 R=4；需改用 1024×1024 图像或降低重复次数——这是"容量—鲁棒性"权衡的直接体现，可作为论文的一个讨论点。

## 6. 与 Polar 码的衔接（下一阶段）

1. 128 bit 信息位 → $(256,128)$ Polar 编码，得到 256 个编码比特；
2. 256 个编码比特按 R 次重复分散到 $256R$ 个块；
3. 提取端得到 256 个软值，乘以 LLR 缩放因子 $\rho$ 后送入 SC 译码。$\rho$ 需要通过实验标定（软值量纲与真实 LLR 不同，但 SC 只依赖相对大小，$\rho$ 主要影响数值稳定性与是否使用 CRC 辅助）。

对比实验的设计要点：**总块数、载荷长度、攻击条件保持一致**，只改变编码层（无编码 = 直通 + 硬判决；Polar = 编码 + SC 译码），这样增益完全归因于纠错码。

## 7. 系统实现（界面部分）

### 7.1 分层

```
┌───────────────────────────────────────────────┐
│ gui.py (PyQt5)                                │
│   图片信息 / 水印内容 / 高级设置 / 结果卡片     │
└───────────────┬───────────────────────────────┘
                │ 只调用公开 API，不碰算法细节
┌───────────────▼───────────────────────────────┐
│ pipeline.py   embed / extract / remove / capacity_bits │
│ codes.py      Codec 接口（无编码 / Polar）      │
└───────────────┬───────────────────────────────┘
┌───────────────▼───────────────────────────────┐
│ dft_watermark.py   分块 DFT 调制与软判决       │
│ metrics.py  attacks.py  payload.py  io_utils.py│
└───────────────────────────────────────────────┘
```

界面层不含任何算法实现，只做参数收集、状态管理与显示，因此同一套核心库既能被脚本批量调用，也能被界面驱动——论文里可以据此说明"算法与界面解耦"。

### 7.2 界面结构

界面按老师要求收敛为"加水印 / 提取信息 / 去水印"三步演示，其余能力全部折叠：

```
┌──────────────────────────────────────────────────────────────────┐
│ 标题      [打开图片][保存图片][保存结果] [加水印][提取信息][去水印][重置] │
├──────────────────────────────┬───────────────────────────────┤
│ 原图   含水印图像             │ 图片（文件 / 尺寸 / 容量）     │
│ 处理结果   差异图(×16)        │ 水印内容（类型 / 文本 / 字节）  │
│                              │ ▸ 高级设置（参数 + 攻击模拟）   │
├──────────────────────────────┴───────────────────────────────┤
│ 提取结果（文本或 32×32 图）              错误 0 / 128          │
├──────────────────────────────────────────────────────────────┤
│ 状态提示              PSNR  SSIM  BER  NC  攻击 PSNR          │
└──────────────────────────────────────────────────────────────┘
```

* **默认只显示原图与含水印图**；"处理结果"（攻击后 / 去水印后）和"差异图"在需要时才出现，避免空白占位。
* **高级设置默认折叠**，包含强度 α、重复次数、选块种子、信道编码与 8 种攻击模拟。
* **提取信息**与**去水印**分开：前者读出文本/logo 并给出 BER/NC，后者抹除水印、显示去除图与去除后的 PSNR。
* 窗口尺寸按 `QApplication.primaryScreen().availableGeometry()` 计算，上限 1240 宽、最小 980×600，并在 `show()` 后用窗口外框再校正一次，高 DPI 缩放下不会超出屏幕。

### 7.3 交互状态

```
图像 orig ──加水印──► 含水印 wm ──攻击──► attacked ──提取信息──► extracted
                            │                 └──去水印──► removed（再提取 BER 0.2–0.6）
                            └──────── 未施加攻击时直接对 wm 处理 ────────┘
```

* `orig` 为空时"加水印"禁用；`wm` 为空时"提取信息/去水印/攻击/保存"禁用。
* 加水印时把 `(codec, max_repeat, seed)` 记录到 `embed_params`，**提取与去水印一律使用记录值**，避免用户事后改参数导致选块错位。
* 攻击结果只影响 `attacked`，不覆盖 `wm`；去水印结果单独存到 `removed`，也不覆盖 `wm`，可以反复对比。
* "保存图片"保存当前成品：有过去除结果就存去除图，否则存含水印图。

### 7.4 显示细节

* 差异图为 `|wm − orig|` 取通道最大值后放大 16 倍并套用 INFERNO 色表，便于观察改动的空间分布（稀疏嵌入时可直观看到"只有部分块被改动"）。
* 二值水印模式在结果卡片右侧显示 32×32 提取图，可直接看出错误位置；文本模式只显示文本。
* 错误比特数（`错误 0 / 128`）常驻结果卡片右上角，答辩时不展开高级设置也能说明提取质量。
* 中文路径通过 `io_utils.imread/imwrite`（`imdecode`/`imencode` + `tofile`）绕开 OpenCV 在 Windows 上对非 ASCII 路径的限制。

### 7.5 性能

512×512、128 bit 载荷、重复 8 次的实测（本机）：

| 操作 | 耗时 |
|---|---|
| 嵌入（含 YCrCb 往返与取整） | ≈ 41 ms |
| 提取 | ≈ 9 ms |
| 单次攻击（JPEG/噪声/滤波） | < 20 ms |

全部同步执行，不需要多线程；界面不会卡顿。


## 8. 已知局限

1. 极平滑块（纯色天空、白墙）中频能量趋近 0，$\Delta$ 被 $0.9\bar m$ 压到很小，几乎不携带信息；当前实现浪费了这部分容量，可以用"能量判据 + 跳过"改进，但提取端需要同步跳过。
2. 不抵抗几何攻击（旋转、平移、大幅缩放）。任务书未要求，实验中也未纳入。
3. 裁剪攻击目前实现为"挖洞填充"，不涉及裁剪后的重采样与网格失同步问题。
4. 灰度图与彩色图共用同一流程，彩色图在 YCrCb 往返与 uint8 取整中会引入微小额外误差（PSNR 影响 < 0.1 dB）。
